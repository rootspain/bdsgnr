# План: расширение типов поверхностей и их определение

Цель — чтобы у каждой поверхности проекта была роль относительно взрыва (буровая поверхность, подошва, откос, пласт, съёмка после взрыва и т. д.), и программа предлагала эту роль сама, а пользователь только подтверждал.

## 1. Что есть сейчас

### Типы поверхностей

`SurfaceKind` (`src/BlastDesigner.Domain/Model/Entities.cs`): `General, Bench, Grade, Topography, Design, Strata, PointCloud`.

Где тип используется:

| Тип | Кто читает |
|---|---|
| `Bench` | первая такая поверхность — поверхность устьев при расстановке скважин (`HoleDesign.CollarSurface`); верх при расчёте объёма |
| `Grade` | первая такая поверхность — подошва, до которой считается длина скважины (`HoleDesign.GradeSurface`); низ при расчёте объёма |
| `Topography` | верх при расчёте объёма, если нет `Bench` |
| `Strata` | «Тип породы по пластам» (`Strata.AssignMaterialByToe`), экспорт пересечений скважин с пластами, окно пересечений; порядок пластов — по отметке в центре блока, каждый раз заново |
| `PointCloud` | заливка облака точек |
| все | цвет заливки по типу (настройки, легенда поверхностей), выбор типа в «Создать поверхность» и в свойствах |

В проекте типы хранятся **по имени** (`JsonStringEnumConverter` в `ProjectJson`), поэтому новые значения можно добавлять в любое место перечисления, а переименовывать существующие нельзя: старые проекты перестанут читаться.

У поверхности нет даты съёмки и нет порядкового номера (A, B, C…).

### Данные бурения: где и когда вносятся

Жизненный цикл скважины — `HoleState`: Проектная → Пробурена → Замерена → Разрешена → Заряжена → Взорвана. Фактические данные бурения вносятся **после бурения и до заряжания**:

| Что | Где в программе | Куда пишется |
|---|---|---|
| Фактическое устье и длина | Файл ▸ Импорт ▸ «IREDES Quality file update holes…» | `ActualCollar`, `ActualLength`, состояние «Пробурена»; при смещённом устье — прямая траектория |
| Фактическая длина (замер) | Импорт текстового файла (колонка «Фактическая длина»); редактор скважины «Фактическая длина»; колонка «Замер» в таблице скважин | `ActualLength` |
| Траектория | инструмент «Траектория скважины»; полилинии траекторий из DXF | `BoreTrack` |
| MWD (скорость проходки, крепость по глубине) | Файл ▸ Импорт ▸ «MWD data, single file…» (CSV: скважина, глубина, скорость, крепость) | `Mwd` |
| Состояние | контекстное меню «Отметить пробуренной» | `State` |
| Сброс | «Очистить фактические данные» | всё перечисленное |

Как фактические данные используются сейчас:

- забой скважины (`Toe`) считается по фактической длине и траектории, если они есть;
- MWD меняет заряд по интервалам крепости (`LoadingAlternates`) и рисуется на профиле;
- геологии по скважинам (интервалов пород) в программе **нет**: `MaterialType` — одно число на скважину, его ставит вручную пользователь или «Тип породы по пластам» по уже готовым поверхностям пластов.

Для определения типов поверхностей это значит:

- **устья и забои** проектных и тем более пробуренных скважин — лучшая привязка буровой поверхности и подошв;
- **пласты** по данным бурения сейчас построить не из чего; MWD даёт только смену крепости по глубине.

## 2. Целевой набор типов

| Роль | Сколько | В модели данных |
|---|---|---|
| Буровая поверхность уступа | 1 | `Bench` (как сейчас) |
| Подошвы бурения A…D | до 4 | `Grade` + `Order` 0…3 |
| Откос (фронт блока) | 1 | `Face` — новый |
| Объём до взрыва | служебный | `PreBlast` — новый, в меню не показывается |
| Съёмка после взрыва (объём после взрыва) | 1 | `PostBlast` — новый |
| Развал | 1 | `Muckpile` — новый |
| Подошва после взрыва | 1 | `PostBlastFloor` — новый |
| Пласты A…X | до 24 | `Strata` + `Order` 0…23 |
| Рельеф | 1 | `Topography` (как сейчас) |
| Прочие | — | `General`, `Design`, `PointCloud` (как сейчас) |

Новые поля `SurfaceEntity`:

- `int? Order` — буква для подошв и пластов; `null` у старых проектов, тогда порядок определяется по отметке, как сейчас;
- `DateTime? SurveyedAt` — дата съёмки; нужна, чтобы отличать съёмку до взрыва от съёмки после (сравнение с `Header.ShotDate`). Заполняется при импорте из даты файла или заголовка DWG, правится в свойствах.

Внешние коды ролей, если понадобится обмен:

| Код | Роль |
|---|---|
| −1 | не задана → `General` |
| 0 | `Bench` |
| 1, 19, 20, 21 | `Grade`, Order 0, 1, 2, 3 |
| 2 | `Face` |
| 3 | `PreBlast` |
| 4 | `PostBlast` |
| 5 | `Muckpile` |
| 6 | `PostBlastFloor` |
| 7…18 | `Strata`, Order 0…11 |
| 22…33 | `Strata`, Order 12…23 |
| 34 | `Topography` |

Таблица соответствия — одна функция в `BlastDesigner.Domain`, с тестом в обе стороны.

## 3. Что поменять в программе ради новых типов

1. `SurfaceKind` + `Order` + `SurveyedAt`, переводы, цвета по умолчанию для новых типов (`ProgramSettings.DefaultSurfaceColors`), легенда показывает букву («Подошва B», «Пласт C»).
2. Свойства поверхности: при типе «Подошва» или «Пласт» появляется выбор буквы; буквы не повторяются внутри типа (при занятой букве предлагается следующая свободная).
3. Расстановка и длина скважин: подошва для скважины — `Grade` с наименьшей буквой, которая есть под устьем; остальные подошвы пока только показываются (несколько подошв в расчёте заряда — отдельная задача).
4. Расчёт объёма: верх — `PreBlast`, иначе `Bench`, иначе `Topography`; низ — подошва A; плюс «объём после взрыва» между `PreBlast`/`Bench` и `PostBlast`, и разрыхление = объём развала / объём в целике.
5. Пласты: «Тип породы по пластам» и экспорт пересечений берут порядок из `Order`, если он задан у всех пластов.
6. Откос: инструменты, которым нужен откос (профиль первого ряда, вид по откосу), сначала берут поверхность `Face`, иначе, как сейчас, — линии бровок.

Старые проекты открываются без изменений: новых полей в них нет, поведение прежнее.

## 4. Как определять каждый тип

Определение — по правилам; для каждой поверхности считаются признаки, по ним выбирается роль с уверенностью и **причиной словами** («устья 46 из 48 на поверхности, среднее отклонение 0,12 м»).

### Признаки поверхности

| Признак | Как считается |
|---|---|
| Привязка устьев | доля скважин, у которых `|Z устья − Z поверхности| < 0,5 м`, и среднее отклонение |
| Привязка забоев | доля скважин, у которых забой на поверхности или ниже её на величину перебура (0…2,5 м); по фактическому забою, если скважина пробурена |
| Уклон | распределение уклонов треугольников по площади: доля < 10°, 10…45°, > 45° |
| Ступенчатость | число уровней в гистограмме отметок (площадки уступов) |
| Шероховатость | отклонение от сглаженной поверхности на окне 5–10 м |
| Охват | площадь, отношение к контуру блока, выходит ли за блок |
| Положение | средняя отметка относительно других поверхностей в контуре блока: выше / ниже / пересекает |
| Пересечение со скважинами | сколько скважин поверхность пересекает между устьем и забоем |
| Время | `SurveyedAt` относительно даты взрыва; порядок импорта, если дат нет |
| Связь с линиями | проходит ли через верхние или нижние бровки (типы линий из «Распознать (AI)») |
| Имя | имя поверхности, слоя или файла: «топо», «рельеф», «подошва», «развал», «пласт», «после взрыва»… — слабый признак |

### Роли

| Роль | Правило | Если скважин нет |
|---|---|---|
| **Буровая** | ≥ 70 % устьев на поверхности; из подходящих — с наибольшей долей и меньшим отклонением | площадка за верхними бровками: малый уклон, выше остальных поверхностей в контуре блока |
| **Подошвы A…D** | ≥ 60 % забоев на поверхности или чуть выше; ниже буровой на 0,5…1,5 высоты уступа; почти горизонтальна. Несколько подходящих поверхностей на разных уровнях — несколько подошв, буквы сверху вниз | площадка перед нижними бровками, на уровне нижних бровок |
| **Откос** | > 50 % площади с уклоном > 45°; узкая вытянутая полоса между отметками буровой и подошвы; проходит через верхнюю и нижнюю бровку | то же |
| **Рельеф** | самая большая по охвату, далеко выходит за блок; содержит несколько уступов или гладкий рельеф | то же |
| **После взрыва** | снята после даты взрыва или импортирована позже буровой; в контуре блока заметно отличается от буровой (> 1 м на ≥ 30 % площади) | то же |
| **Развал** | съёмка после взрыва, участок которой выше прежней поверхности перед откосом; шероховатая, выпуклая, склоны 30…40° | то же |
| **Подошва после взрыва** | съёмка после взрыва, на отметке подошвы ± 1 м в контуре блока, ровная | то же |
| **Пласты A…X** | гладкая, без ступеней; пересекает тело уступа: ≥ 30 % скважин пересекают её между устьем и забоем на разной глубине; не совпадает с линиями съёмки. Буквы — сверху вниз по средней отметке в контуре блока | только по имени, иначе «Общая» |
| **Объём до взрыва** | не распознаётся: создаётся при расчёте объёма копией буровой или рельефа | — |

Конфликты (две поверхности на роль одного экземпляра) решаются по уверенности; проигравшей предлагается следующая подходящая роль или «Общая».

### Чем помогает распознавание линий

Из типов линий, которые даёт «Распознать (AI)», можно не только проверять, но и **строить** поверхности, которых в проекте нет:

- буровая — по верхним бровкам и пикетам площадки за ними, обрезанная по бровке;
- подошва — по нижним бровкам и пикетам перед ними;
- откос — по паре «верхняя — нижняя бровка» (пары уже находит расчёт уступов).

### Пласты по данным бурения (позже)

Сейчас строить не из чего. Два возможных источника:

1. **Импорт интервалов пород** (CSV: скважина, от, до, порода) — новое поле интервалов у скважины. Контакт пород в каждой скважине даёт точку; по точкам одного контакта строится поверхность пласта.
2. **MWD**: смена крепости по глубине, устойчивая по соседним скважинам, — кандидат контакта. Только подсказка, пласт подтверждает пользователь.

## 5. Интерфейс

- Команда **«Определить типы поверхностей…»** на вкладке «Топография», группа «Поверхности», и в меню «Инструменты ▸ Поверхности».
- Окно: таблица поверхностей — имя, сейчас, предложено, уверенность, причина; выпадающий список для правки; буквы подошв и пластов. Выбранная строка подсвечивает поверхность на плане.
- Флажки: «Построить недостающие (буровая, подошва, откос) по бровкам»; «Применить».
- Применение — один шаг отмены.
- После импорта DWG/DXF или облака точек — ненавязчивая подсказка в строке состояния: «Найдено N поверхностей без типа — Определить типы…».

## 6. Модель: нужна ли

На первом этапе — **нет**. Роли определяются связями (скважины, время, взаимное положение), форма поверхности — вспомогательный признак, и правила здесь объяснимы и проверяемы.

Модель имеет смысл в одном месте: отличить **развал** от прочих съёмок после взрыва по форме. Это возможно, когда появятся реальные съёмки после взрыва; синтетику можно сделать (генератор развала по профилю выброса), но без реальных примеров результат непроверяем — та же ситуация, что с бровками.

## 7. Проверка

- **Синтетические сцены**: генератор блока — рельеф с уступами, буровая, 1–3 подошвы, откос, 0–3 пласта, скважины (с отклонениями устьев и забоев), съёмка после взрыва с развалом. Метрика — доля правильно определённых ролей, отдельно для каждой роли; тест с порогом.
- **Ловушки**: проектная поверхность рядом с буровой; две подошвы на близких отметках; пласт, почти горизонтальный на уровне подошвы; съёмка после взрыва без даты.
- **Реальный пример** (`samples/real1.dwg`, не в репозитории): поверхность по съёмке должна определяться как рельеф, а построенные по бровкам — как буровая, подошва и откос.
- **Старые проекты** открываются и считаются так же, как раньше (тест на чтение проекта без новых полей).

## 8. Этапы

| № | Что | Результат |
|---|---|---|
| 1 | Новые типы, `Order`, `SurveyedAt`, переводы, цвета, свойства, коды обмена | типы можно назначать вручную; старые проекты как прежде |
| 2 | Потребители: подошва A для длин скважин, объём с `PreBlast`/`PostBlast`, разрыхление, порядок пластов из `Order`, откос для профиля | расчёты используют новые типы |
| 3 | Признаки поверхности и правила ролей; окно «Определить типы поверхностей» | программа предлагает роли с причинами |
| 4 | Построение буровой, подошвы и откоса по распознанным бровкам | недостающие поверхности строятся из съёмки |
| 5 | Генератор синтетических сцен, метрики, тесты с порогом | измеримая точность |
| 6 | Импорт интервалов пород; пласты по контактам; подсказки по MWD | пласты из данных бурения |
| 7 | (по данным) модель для развала | только при наличии реальных съёмок после взрыва |

Этапы 1–3 дают основную пользу; 4–5 можно делать параллельно с 3; 6–7 — по мере появления данных.

## 9. Риски

- **Несколько подошв в расчёте заряда.** Сейчас длина скважины считается до одной подошвы. Скважины через несколько уровней — отдельная задача; на этапе 2 используем подошву A.
- **Нет дат съёмки.** Без `SurveyedAt` съёмку после взрыва отличаем только по разнице с буровой; при сомнении — «Общая», решает пользователь.
- **Нет скважин.** Тогда буровая и подошвы определяются только по бровкам и положению — уверенность ниже, это показывается в причине.
- **Пласты.** Без геологических данных пласты определяются только по форме и имени, надёжность низкая.
